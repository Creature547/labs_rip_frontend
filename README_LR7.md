# ЛР7 · Отопительные приборы

Архив распаковывается в корень labs_rip_frontend. Рядом должны лежать frontend/, docs/ и .github/. ЛР7 продолжает исправленный фронтенд ЛР6. Для локального режима используется существующий Go-бэкенд, база и хранилища из шестой работы.

## Сначала проверить деморежим

В WSL из frontend/ выполнить при Node.js 24:

```bash
npm ci
npm run build:pages
npm run preview -- --host 127.0.0.1
```

Открыть адрес из терминала на ноутбуке. Нажать «Плитка», ввести минимальную мощность 20 и нажать «Найти». Останутся бойлер (24 кВт) и теплогенератор (200 кВт). Открыть «Подробнее» у бойлера, нажать «К плитке» — число 20 и обе карточки сохранятся. Плитка и лента работают с mock, вход доступен в локальном режиме с бэкендом. После первого открытия и завершения установки service worker оболочка, картинки и каталог доступны без сети. Видео загружаются при наличии сети. Остановить preview сочетанием Ctrl+C.

## GitHub Pages

В настройках репозитория GitHub выбрать Settings → Pages → Build and deployment → Source → GitHub Actions. Из корня репозитория проверить git diff и git status. В коммит включить frontend, docs, README_LR7.md и .github/workflows/lab7-pages.yml. Отправить ветку lab7-responsive-pwa-https в origin. Workflow соберёт демоверсию командой npm run build:pages и развернёт dist. В Actions открыть успешный запуск Deploy heating equipment PWA и ссылку github-pages. Открыть её на телефоне. В Safari использовать «Поделиться» → «На экран Домой», в Chrome для Android — пункт установки приложения в меню браузера.

## Локальный HTTPS с бэкендом

1. Запустить бэкенд и хранилища как в ЛР6. Из WSL должны быть доступны Go на 127.0.0.1:8080 и MinIO на 127.0.0.1:9000. Телефон и ноутбук подключить к одному Wi-Fi.
2. На Windows выполнить ipconfig и взять IPv4 адаптера Wi-Fi. В WSL из frontend/ выполнить команды ниже, подставив фактический адрес вместо примера.

```bash
bash scripts/lan-cert.sh 192.168.1.10
npm run dev:https
```

3. На телефон передать только frontend/certs/root.crt. Закрытые ключи root.key и lan-key.pem остаются на ноутбуке. На iOS установить профиль сертификата и включить доверие к этому корню в «Настройки → Основные → Об этом устройстве → Доверие сертификатам». На Android установить root.crt как сертификат ЦС в настройках безопасности. После защиты учебный корень можно удалить. Для проверки в браузере Windows импортировать root.crt в доверенные корневые центры текущего пользователя.
4. В браузере телефона открыть https://192.168.1.10:5173 с фактическим IP. На странице «Вход» авторизоваться учётной записью ЛР6. Проверить ленту, плитку и добавление. Из браузера все запросы идут на тот же HTTPS-адрес. Vite пересылает /api на Go, /s3 на MinIO. При смене IP выполнить скрипт с новым адресом и перезапустить Vite; он повторно использует существующий учебный корень.
5. Если ноутбук открывает приложение, а телефон получает тайм-аут, проверить доступ к порту WSL. Для обычного режима NAT в PowerShell от администратора можно пробросить только порт 5173. Подставить IPv4 Wi-Fi Windows и IPv4 WSL (в Ubuntu выполнить hostname -I и выбрать адрес eth0). Правило рассчитано на домашнюю сеть с профилем Private.

```powershell
$wifiIp = '192.168.1.10'
$wslIp = '172.24.100.20'
netsh interface portproxy add v4tov4 listenaddress=$wifiIp listenport=5173 connectaddress=$wslIp connectport=5173
New-NetFirewallRule -DisplayName 'РИП ЛР7 HTTPS' -Direction Inbound -Action Allow -Protocol TCP -LocalAddress $wifiIp -LocalPort 5173 -RemoteAddress LocalSubnet -Profile Private
```

После демонстрации проброс и правило можно убрать в том же PowerShell.

```powershell
netsh interface portproxy delete v4tov4 listenaddress=$wifiIp listenport=5173
Remove-NetFirewallRule -DisplayName 'РИП ЛР7 HTTPS'
```

## Скриншоты для демонстрации

| № | Что должно быть видно |
|---|---|
| 1–2 | GitHub Pages на телефоне с каталогом mock, затем установка или значок PWA на домашнем экране |
| 3–6 | PWA открыто с домашнего экрана, фильтр 20 кВт и две карточки, подробности бойлера, возвращение к тому же фильтру и результатам |
| 7 | Device Toolbar в DevTools, ширина и сетка плитки. Изменить ширину между 390, 760 и 1100 px |
| 8–12 | Вход с телефона по IP ноутбука, экран после входа, лента, плитка и форма добавления с активным бэкендом. Пароль скрыт |
| 13–14 | vite.config.ts с https.key и https.cert и проверка SAN командой openssl x509 -in certs/lan.pem -noout -ext subjectAltName, затем сведения о защищённом соединении браузера |
| 15–17 | src/App.css с .equipment-grid и двумя медиазапросами, фактический размер выбранной карточки в DevTools, подсветка Grid в широкой плитке |

Порог 640 px переключает две колонки на три, 960 px — три на четыре. Колонки делят доступную ширину поровну (1fr). Карточка сохраняет пропорции 1:1 через aspect-ratio, поэтому обе её стороны плавно меняются даже между порогами. Например, при ширине плитки 760 px три колонки с двумя промежутками по 14 px дают ширину и высоту карточки 244 px. В широкой ленте видео расположено по центру, а параметры и действия вынесены справа.
